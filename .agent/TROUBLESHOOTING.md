# Biker Navigation - Troubleshooting & Limitations

## 1. 프론트엔드 렌더링 최적화
- **문제 현상**: 카카오 지도에서 5만 개 이상의 공공데이터 마커(카메라, 스쿨존 등)를 한 번에 렌더링하면 모바일 브라우저가 버티지 못하고 강제 종료되거나 심각한 렉(Lag)이 발생.
- **원인 분석**: 브라우저 DOM 객체가 기하급수적으로 늘어나 메모리 한계 초과 및 메인 스레드 블로킹 발생.
- **해결 방안**: 
  - `map.getBounds()`를 활용하여 화면(뷰포트)에 들어온 좌표만 필터링 후 렌더링.
  - 내비게이션 주행 시(경로 탐색 시)에는 반경 30~50m 이내의 '경로 상 데이터'만 렌더링하도록 2차 공간 필터링(Spatial Filtering)을 적용하여 UI 시각적 공해를 없애고 극강의 최적화 달성.

## 2. 공공데이터(JSON) 원천 가비지 컬렉션 (Garbage Collection)
- **문제 현상**: 정부 공공데이터포털의 '전국무인교통단속카메라' 데이터에는 오토바이 주행과 전혀 무관한 '화물차 적재불량', '중량위반', '버스전용차로' 단속 카메라가 섞여 있어 이륜차 운전자에게 불필요한 경고를 유발함.
- **원인 분석**: 단속구분 코드가 1(과속), 2(신호위반) 외에도 99(기타), 3, 4 등으로 뭉뚱그려져 있음.
- **해결 방안**: Node.js 전처리 파이프라인(`process_data.cjs`)에 지능형 오토바이 필터를 주입. 단속목적/설치장소 텍스트를 파싱하여 '후면', '이륜', '안전모' 키워드가 없으면서 과속/신호위반 코드가 아닌 데이터는 원천 Drop 처리함.
- **결과**: 총 12,673개의 불필요한 쓰레기 데이터를 원천 제거(약 30% 감축)하여, 정적 파일 용량 감소 및 렌더링 성능 대폭 상향 성공.

## 3. 실시간 GPS 내비게이션 노이즈 및 상태 지연
- **해결 방안**: 내 위치 마커의 회전 각도(Heading) 및 좌표 이동은 `useState` 대신 `useRef`와 순수 DOM 조작을 통해 60fps로 트래킹 최적화.

## 4. 기능 한계 및 추후 고도화 방안 (Limitations & Future Work)
- **교통상황별 경로 색상 미지원**: 오픈소스 BRouter 엔진의 한계로 T맵 등과 같은 구간별 정체 현황 색상(빨강/초록) 표출은 불가능함. 추후 B2B 실시간 교통 API 별도 계약 필요.
- **일방통행/유턴 구역 부정확성**: 국내망 특화 엔진이 아닌 OSM 기반이므로, 한국 특유의 골목길 통제가 완벽히 반영되지 않음. 대신 기하학(벡터 내적) 연산을 통한 '🚨 불법U턴 주의' 레이더를 클라이언트 사이드에 자체 구현하여 방어 운전 유도 완료.
- **실시간 음성안내(TTS) 한계**: Web Speech API 사용으로 PWA 백그라운드 환경에서 OS 정책상 음성 출력이 중단될 한계가 존재함. 추후 React Native 패키징을 통한 백그라운드 워커 고도화 요망.
